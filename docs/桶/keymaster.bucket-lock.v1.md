# 桶锁

同一时间只允许**一个浏览器使用**这个桶:读和写都算。

原因:读取也是异步的——client A 做了操作,client B 并不知道,也没有同步机制;所以规定 KeyMaster 同一时间只有一个 client 使用这个桶(应用锁)。

锁是桶内的一个文件,持有者用浏览器 session 标识(见《浏览器session》)。

**例外(不抢应用锁)**:导入/接入桶时读取 `keys/` 下的 KeyHold 文件、备份、导出桶——这些只读操作任何浏览器都可以做。

## 位置与格式

```
桶根/keymaster/lock.json
```

```jsonc
{
  "format": "keymaster.bucket-lock",
  "version": 1,
  "holder": "3f8a1c9d2e4b6a708192a3b4c5d6e7f8",
  "acquiredAt": 1757900000000,
  "heartbeatAt": 1757900000000,
  "expiresAt": 1757900060000
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `format` | 字面量 | 是 | 固定 `"keymaster.bucket-lock"` |
| `version` | 数字 | 是 | 固定 `1` |
| `holder` | 字符串 | 是 | 持有者浏览器 session id,32 位小写 hex |
| `acquiredAt` | 数字 | 是 | 首次获取锁的时间(毫秒) |
| `heartbeatAt` | 数字 | 是 | 最近一次续约时间(毫秒) |
| `expiresAt` | 数字 | 是 | 过期时间(毫秒)= `heartbeatAt` + 60 秒 |

## 规则

- **锁是应用操作的前置条件**:没有锁时不允许正常使用(读和写都禁止),只能做例外的只读操作。
- **TTL 60 秒,心跳 45 秒**:持有者每 45 秒更新 `heartbeatAt` / `expiresAt`。
- **获取**(在开始使用之前):
  1. 读 `lock.json`;
  2. 不存在,或 `expiresAt <= 现在` → 写入自己(抢占过期锁);
  3. 存在且未过期、`holder` 是自己 → 续约;
  4. 存在且未过期、`holder` 是别人 → 拒绝使用,显示“桶正被另一个浏览器使用”。
- **续约失败 = 失去锁**:条件写失败(被抢)时立即停止全部应用 I/O(读和写),回到“被占用”提示。
- **释放**:用户主动锁定钱包 / 关闭会话时删除文件;崩溃或断网则等过期自动释放。
- **原子性**:创建用条件写(`If-None-Match: *`),续约/抢占用 `If-Match`;存储不支持条件写时退化为读后写,存在极小概率同时持有(按《存储规则》接受)。
- **多标签页**:cookie 相同 = 同一持有者,由 Worker 内写队列串行(见《存储规则》),不需要重复抢锁。
- **时钟**:`expiresAt` 用本机时间比较;不同设备时钟偏差可能导致提前或延迟抢占,接受。

## 校验规则

1. 字段白名单;格式与版本匹配。
2. `holder` 匹配 `^[0-9a-f]{32}$`。
3. 时间戳为非负整数,且 `expiresAt >= heartbeatAt >= acquiredAt`。
4. 文件不合法时按“无锁”处理并覆盖。

## 设计取舍

- **应用锁包含读**:读取也是异步的,A 的操作 B 不知道;没有同步机制,就只能规定一个 client。
- **互斥放在桶里而不是本地**:跨浏览器、跨设备唯一有效;回避 S3 的多客户端竞争。
- **例外保持只读**:导入/接入读 `keys/` 下的 KeyHold 文件、备份、导出桶不经过应用锁,不影响持有者。
- **不记录所有者公钥**:锁管的是“哪个浏览器在使用”,与钱包 key 无关;同一浏览器换 key 不需要重新抢锁。
- **只做互斥,不做排队**:拿不到就提示,不自动等待接管;等对方过期后重试即可。
- **崩溃释放靠过期**:不依赖清理任务,也不依赖对方正常退出。
