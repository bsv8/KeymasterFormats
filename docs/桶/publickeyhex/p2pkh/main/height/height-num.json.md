# `桶/<owner 公钥>/p2pkh/main/height/<height>.json` — 我的交易在区块里的位置

记录"哪些区块包含我的交易、以及区块里这些交易的顺序"。tx 文件只有 raw tx、不含区块信息,区块顺序由本文件提供。

- 只收录**包含我的交易**的区块;没有我的交易的区块不建文件。
- 数组顺序 = 区块内交易顺序;同一区块内一笔交易可以花上一笔的输出,回放时必须按这个顺序。

## 位置与命名

```
桶根/<owner 公钥>/p2pkh/main/height/<height>.json
```

| 部分 | 规则 |
| --- | --- |
| `<owner 公钥>` | 当前 active key 的压缩公钥,小写 |
| `main` | 网络;测试网用 `test` |
| `<height>` | 区块高度,10 位零填充(`0008500000`),保证列举顺序 = 高度顺序 |

## 文件格式

```json
[
  "9f1c8d2a4b6e7f8091a2b3c4d5e6f708192a3b4c5d6e7f8091a2b3c4d5e6f708"
]
```

- 纯 JSON 数组,元素是 txid(64 位小写 hex),文件内不重复。
- 每个元素都必须能在 `tx/<txid>.json` 找到对应文件;找不到按损坏处理。
- **空数组不合法**:没有我的交易就不建这个文件。

## 写入规则

- 新区块包含我的交易:写 `height/<height>.json`,数组按区块内顺序。
- 同一高度重复同步:直接覆盖(幂等)。
- reorg:高度失效 → 删除或按 provider 结果改写。
- 并发:同一文件按《存储规则》处理(Worker 内串行,跨设备最后写入者胜);被覆盖的条目可以重新同步修复。

## 读取

1. 列举 `height/` 得到全部高度文件(按文件名即高度排序);
2. 每个文件给出该区块里我的交易及回放顺序;
3. 与 `tx/<txid>.json` 拼出完整历史,并在内存建立 `txid → height` 映射;
4. 确认数 = provider 当前 tip − 高度。

## 校验规则

1. 文件名匹配 `^\d{10}\.json$`。
2. 内容是数组,元素为 `^[0-9a-f]{64}$` 且不重复,数组非空。
3. 单个文件不合法:跳过并提示,不影响其它高度。

## 设计取舍(消融记录)

- **单独建 `height/` 目录**:tx 文件保持"只有 raw tx",地址、输入输出、UTXO 状态仍全部不落盘。
- **保留区块内顺序**:同块内花费顺序是业务语义,不能丢。
- **只收有我的交易的块**:目录大小与我的交易量成正比,而不是跟随全链。
- **不设 `format`/`version`**:文件语义由固定路径和数组形状表达,保持最小。
- **代价**:每有一个含我交易的区块就多一个文件;同一高度是"读-改-写",跨设备可能丢条目,依赖重新同步修复。

## 完整示例

路径:

```
桶/<owner 公钥>/p2pkh/main/height/0008500000.json
```

内容:

```json
[
  "9f1c8d2a4b6e7f8091a2b3c4d5e6f708192a3b4c5d6e7f8091a2b3c4d5e6f708",
  "3f8a1c9d2e4b6a708192a3b4c5d6e7f890a1b2c3d4e5f60718293a4b5c6d7e8f"
]
```
