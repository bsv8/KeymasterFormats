# `桶/<owner 公钥>/msfiles/seeds/<seedhash>.ms` — MasterSeed 种子文件

MasterSeed `keymaster-seed-v1` 种子字节的桶内存储：文件名是种子哈希，内容就是原始二进制种子字节，
不含任何头部、元数据或 hex 文本。

## 位置与命名

```
桶根/<owner 公钥>/msfiles/seeds/<seedhash>.ms
```

| 部分 | 规则 |
| --- | --- |
| `<owner 公钥>` | 当前 active key 的压缩公钥，小写 |
| `msfiles/seeds` | 固定目录 |
| `<seedhash>` | 文件内容的 MasterSeed `seed_hash`，64 位小写 hex |
| `.ms` | 固定后缀，标记这是种子字节而不是普通 JSON 或业务文件 |

- 文件名不是源文件名，也不是块数量，而是内容身份：同名文件必然同字节。
- 列表真值是 `meta/<seedhash>.json`；本文件表示种子的内容是否可用。本文件是否存在是
  **读取时懒检测**：缺失时条目显示“种子丢失”，不可读取，但不从列表消失，也不影响列表成本。

## 文件内容

内容就是 `keymaster-seed-v1` 的原始种子字节：

```text
seed_bytes = SHA256(block[0]) || SHA256(block[1]) || ... || SHA256(block[n-1])
```

- 源文件按固定边界 `262144` 字节（256 KiB，不是 256000 字节）分块；
- 每个块计算 SHA-256，得到 **32 字节原始摘要**，按块号顺序直接拼接；
- 空文件合法：0 个块，种子文件长度为 0；
- `seed_size = blockCount × 32`，`seed_hash = SHA256(seed_bytes)`。

下列写法不得写入种子文件：`"ba7816bf…"` 这类 hex 文本。hex 只是摘要的展示与文件名编码；
把 hex 文本写进文件会让每个块占 64 字节，不再是 V1 格式。

种子字节不包含源文件名、源文件大小、媒体类型、时间戳、块数量、块大小、算法或版本；
除块大小与算法是协议常量外，其余描述信息保存在
[meta/<seedhash>.json](../meta/seedhash.json.md)。

## 规则

- **命名**：文件名匹配 `^[0-9a-f]{64}\.ms$`；`<seedhash>` 一律小写。
- **写入**：先写完全部块，再写本文件；同内容重复写入幂等覆盖，不需要条件写，不建索引。
- **不修改**：文件一旦写入不再改写；内容寻址保证同名必然同字节。
- **不重命名**：改名即改变身份，等同于另一个种子。
- **删除**：删除条目时先删元数据（条目立即从列表消失），再删本文件，最后删块，见
  [meta/seedhash.json.md](../meta/seedhash.json.md)。
- **并发**：同一文件在 Worker 内串行，跨设备最后写入者胜（见《存储规则》）。
- **机密性**：种子只是块摘要序列，不包含源内容；仍按业务数据对待，不做额外加密。

## 校验规则

1. 文件名匹配 `^[0-9a-f]{64}\.ms$`。
2. 文件长度为 32 的整数倍；空文件（0 字节）合法。
3. 对文件字节计算 SHA-256，结果必须等于文件名去掉 `.ms` 后的 64 位 hex；不等按损坏处理，
   不展示、不组装。
4. 需要组装原文件时：从本文件按序解析块摘要，从 `storage/<seedhash>/` 取块并逐块重算
   SHA-256 比对；块顺序、数量与最后块期望长度由元数据的 `fileSizeBytes` 共同确定。
5. 与元数据交叉校验：`seedSizeBytes` 等于文件实际长度，`blockCount` 等于长度除以 32；
   不一致按损坏处理。

## 设计取舍（消融记录）

- **文件名 = seed_hash**：内容寻址，天然去重与跨设备幂等，不需要 CAS 或时间戳命名。
- **存原始摘要而不是 hex**：与 V1 字节兼容，体积减半；hex 只出现在文件名与展示中。
- **单独 `seeds/` 目录**：列表只需前缀 `meta/`；本目录只用于标记种子是否可用，
  不会翻到 `storage/` 下的块对象。
- **不夹带元数据**：种子格式没有头部，放进文件名/类型/长度会改变字节和 `seed_hash`；
  描述信息放独立旁车，种子仍可被任何 MasterSeed 实现直接验证。
- **完整性不等于身份**：`seed_hash` 只证明内容一致，不证明发布者身份；身份需要外层协议签名。

## 完整示例

以官方测试向量 UTF-8 `abc` 为例：

```text
源文件大小    3
块数          1
块摘要 hex    ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad
种子文件长度  32
seed_hash     4f8b42c22dd3729b519ba6f68d2da7cc5b2d606d05daed5ad5128cc03e6c6358
```

路径：

```
桶/<owner 公钥>/msfiles/seeds/4f8b42c22dd3729b519ba6f68d2da7cc5b2d606d05daed5ad5128cc03e6c6358.ms
```

文件内容是 32 字节原始摘要；写成 hex 只是为了展示：

```text
ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad
```

对应的块文件见
[storage/masterseedhash/hash.md](../storage/masterseedhash/hash.md)。
