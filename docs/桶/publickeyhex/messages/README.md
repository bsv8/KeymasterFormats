# `桶/<owner 公钥>/messages/` — 私密消息记录

ChannelProtocol 私密消息在桶内的**只增证据目录**：原始数据（raw）与本地时间索引（timeindex）
分开存放，按对端公钥隔离，永不删除、永不重建索引。

## 位置与结构

```
桶根/<owner 公钥>/messages/
└── <对端公钥>/                        # 已验签确认的对端
    ├── sent/<seedhash>.json           # 出站：签名明文（可读、可验签）
    ├── received/<seedhash>.json       # 入站：收到的加密信封（密文）
    └── timeindex/<时间戳>-<message_id>.json
```

| 目录 | 内容 | 说明 |
| --- | --- | --- |
| `<对端公钥>/sent` | 出站私信的签名明文精确字节 | 作者证据；不需要解密即可阅读、验签 |
| `<对端公钥>/received` | 入站私信的加密信封精确字节 | 线上收到的原始字节；用 owner 私钥解密验签 |
| `<对端公钥>/timeindex` | 本地时间索引，一条消息一个文件 | 本机观察证据，只追加、不修改、不删除 |

`<对端公钥>` = 对方压缩公钥，66 位小写 hex（`02` / `03` 开头）。发件方向写收件人公钥，
收件方向写**验签确认后**的发件人公钥。

## 两个原物 + 一个本地观察

- **出站原物**：签名明文（`signPrivateMessage` 的规范 JSON 字节）。你是作者，内容明文可读，
  用你自己的公钥即可验签；不依赖解密。
- **入站原物**：收到的加密信封（`marshalEnvelope` 的精确字节）。只有 owner 私钥能解密，
  解密后验签结果必须等于目录名，才算归属成功。
- **时间索引**：`timestamp` 一律取**本机时间**——出站取发布被本地接受的时间，入站取本机收到的时间；
  不使用对方在消息里声明的时间。索引是本地观察证据，不是可以重算的缓存。

## 文件名 = 内容哈希

- raw 文件名 = 文件内容的 **MasterSeed seed_hash**，64 位小写 hex，扩展名 `.json`；
  定义见 [MasterSeed](https://github.com/bsv8/MasterSeed) 的 `keymaster-seed-v1`。
- 只保存 seed_hash 本身，不需要额外保存 seed 文件；读取时重算并校验。
- `timeindex` 文件名 = `13 位补零毫秒时间戳` + `-` + `message_id` + `.json`，见
  [timeindex/timestamp-messageid.json](./peerpublickeyhex/timeindex/timestamp-messageid.json.md)。

## 写入顺序与只增规则

1. **先写 raw，再写 timeindex**。崩溃只会留下"有 raw、无 index"，不会留下"有 index、无 raw"。
2. raw 允许重复写入；同名即同内容，覆盖是幂等的。实现可以直接覆盖，不需要条件写。
3. timeindex 只追加：每条到达（含重复投递）追加一条；同毫秒用 `<时间戳>-<message_id>` 避免互相覆盖。
4. **没有删除操作**。删 Key / 删桶时整个目录一起消失；这是本模块唯一的清零方式。

## 读取与缺失

- 列出 `timeindex/` 就是会话时间线，文件名排序即时间顺序，不需要读 raw。
- 同一条消息可能有多条索引（重复投递、多设备各自观察）：按 `message_id` 去重，
  取最早 `timestamp` 作为"首次收到"。
- **index 存在、raw 缺失**：条目保留，内容显示"缺失"；不从 raw 反向重建索引。
- **raw 存在、index 缺失**：不扫描、不补索引；未进时间线的 raw 不参与展示（文件保留）。
- raw 读取时重算 seed_hash，与文件名不一致按损坏处理，跳过并提示，不影响其它文件。
- 不保存、不读取任何跨文件索引；一个文件损坏不影响其它文件。
- 整个 Key 删除时随目录消失，不做单条消息删除，也不做引用计数和孤儿回收。

## 对端归属

- 入站消息只有在**解密并验签通过**、且 `from_public_key` 与归属对端一致后，才写入
  `<对端公钥>/received` 并记录时间索引。
- 解不开、验签失败、`from_public_key` 与投递频道不符、或不属于当前 owner inbox 的投递，
  **直接丢弃，不写入桶内任何位置**：这些字节不属于任何对端，保留它们只会引入无法信任的数据。

## 大小与并发

- 单个 raw 文件不超过 1 MiB（SSP Wire 上限）；普通文本消息通常远小于 256 KiB。
- 单个 timeindex 文件不超过 1 KiB。
- 不同文件互不冲突；同一文件重复写是幂等覆盖。多设备各自记录自己的观察，读取时合并去重。

## 与协议的关系

- 出站签名明文、入站加密信封的字段与规范见 ChannelProtocol 私密收件箱；
  本目录只负责"原样保存 + 时间索引"，不重新签名、不重新加密、不改写字节。
- 入站信封是密文：bucket 被第三方读取时看不到正文；出站签名明文是明文，这是为了
  在 owner 私钥丢失后仍能阅读和验证自己发出的消息。

## 设计取舍（消融记录）

- **只增不删**：时间是本地观察，索引即证据；删除或重建都会销毁证据。
- **不重建索引**：收到时间无法从 raw 反推，索引不是缓存。
- **raw 与 index 双轨**：raw 保证内容完整性（内容寻址），index 保证时间顺序（文件名排序）。
- **出站存签名明文而不是发布信封**：owner 无法用 `open()` 解自己的信封；签名明文无需解密、
  私钥丢失后仍可读，内容与身份证据完整；发布信封与它的差别只有随机 salt/nonce 和密文。
- **对端目录隔离**：会话边界就是目录，列表、删除、备份都以目录为单位。
- **无法归属直接丢弃**：`from_public_key` 只是自称，未验签的内容不属于任何对端；不落桶避免把
  冒充或损坏数据当成证据，也避免为"不可信数据"设计保留与清理规则。
