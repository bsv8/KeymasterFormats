# `桶/<owner 公钥>/lock.json` — Key 应用锁

同一时间只允许**一个浏览器使用**这把 Key:读和写都算。

原因:读取也是异步的——client A 做了操作,client B 并不知道,也没有同步机制;所以规定同一把 Key 同一时间只有一个 client 使用(应用锁)。不同 Key 的数据互不相交,两个 client 可以各用一把 Key 并行工作,互不影响。

锁是该 Key 目录里的一个文件,持有者用浏览器 session 标识(见《浏览器session》)。

**例外(不抢应用锁)**:导入/接入桶时读取 `keys/` 下的 KeyHold 文件、备份、导出桶——这些只读操作任何浏览器都可以做。

## 位置与格式

```
桶根/<owner 公钥>/lock.json
```

`<owner 公钥>` = 这把 Key 的压缩公钥,66 位小写 hex(`02` / `03` 开头),与 `keys/<公钥>.keyhold` 的文件名相同。

```jsonc
{
  "format": "keymaster.key-lock",
  "version": 1,
  "holder": "3f8a1c9d2e4b6a708192a3b4c5d6e7f8",
  "acquiredAt": 1757900000000,
  "heartbeatAt": 1757900000000,
  "expiresAt": 1757900060000
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `format` | 字面量 | 是 | 固定 `"keymaster.key-lock"` |
| `version` | 数字 | 是 | 固定 `1` |
| `holder` | 字符串 | 是 | 持有者浏览器 `sessionId`,32 位小写 hex(见《浏览器session》) |
| `acquiredAt` | 数字 | 是 | 首次获取锁的时间(毫秒) |
| `heartbeatAt` | 数字 | 是 | 最近一次续约时间(毫秒) |
| `expiresAt` | 数字 | 是 | 过期时间(毫秒)= `heartbeatAt` + 60 秒 |

## 规则

- **锁是该 Key 应用操作的前置条件**:没有锁时不允许正常使用这把 Key(读和写都禁止),只能做例外的只读操作;不同 Key 的锁互不影响。
- **TTL 60 秒,心跳 45 秒**:持有者每 45 秒更新 `heartbeatAt` / `expiresAt`。
- **获取**(在开始使用这把 Key 之前):
  1. 读 `lock.json`;
  2. 不存在,或 `expiresAt <= 现在` → 写入自己(抢占过期锁);
  3. 存在且未过期、`holder` 是自己 → 续约;
  4. 存在且未过期、`holder` 是别人 → 拒绝使用,显示“该 Key 正被另一个浏览器使用”。
- **切换 Key**:先获取新 Key 的锁,成功后再释放旧 Key 的锁;新 Key 抢不到就留在旧 Key 并提示,不进入无锁状态。
- **创建 / 导入 Key**:写 `keys/<公钥>.keyhold` 前先获取新 Key 的锁。
- **删除 Key**:先获取该 Key 的锁;抢不到说明有人正在使用,拒绝删除。删除顺序:先删 `keys/<公钥>.keyhold`(Key 立即不可见),再删该 Key 数据目录——锁文件随目录一起删除;中途崩溃留下的数据不可见,没有清理任务(接受)。
- **续约失败 = 失去锁**:条件写失败(被抢)时立即停止该 Key 的全部应用 I/O(读和写),回到“被占用”提示。
- **释放**:用户主动锁定钱包 / 关闭会话 / 切换到别的 Key 时删除文件;崩溃或断网则等过期自动释放。
- **原子性**:创建用条件写(`If-None-Match: *`),续约/抢占用 `If-Match`;存储不支持条件写时退化为读后写,存在极小概率同时持有(按《存储规则》接受)。
- **多标签页**:同一浏览器共享同一份 session(见《浏览器session》),天然算同一个持有者,由 Worker 内写队列串行(见《存储规则》),不需要重复抢锁。
- **时钟**:`expiresAt` 用本机时间比较;不同设备时钟偏差可能导致提前或延迟抢占,接受。

## 校验规则

1. 字段白名单;格式与版本匹配。
2. 路径必须是 `<owner 公钥>/lock.json`,目录名匹配 `^(02|03)[0-9a-f]{64}$`;文件内不重复记录公钥。
3. `holder` 匹配 `^[0-9a-f]{32}$`。
4. 时间戳为非负整数,且 `expiresAt >= heartbeatAt >= acquiredAt`。
5. 文件不合法时按“无锁”处理并覆盖。

## 设计取舍

- **锁按 Key 分开**:同一把 Key 的异步读写没有同步机制,必须单 client;不同 Key 的数据互不相交,天然可以并行(client A 用 Key X、client B 用 Key Y 互不影响)。
- **锁文件放在 Key 目录**:与它保护的数据同目录,删除 Key 时随目录一起清理;代价是备份/导出会带上锁文件,恢复后旧锁最多挡 60 秒(TTL),接受。
- **真值只在路径**:目录名就是这把 Key 的公钥,锁文件内不重复记 `publicKeyHex`,避免两处不一致。
- **例外保持只读**:导入/接入读 `keys/` 下的 KeyHold 文件、备份、导出桶不经过应用锁,不影响持有者;备份/导出看到的是移动快照,接受。
- **不做桶级锁**:不同 Key 并行是目标,桶级锁会重新把它们串起来;两个 client 同时创建同一个空桶时会各自生成一把 Key,结果不损坏,接受。
- **只做互斥,不做排队**:拿不到就提示,不自动等待接管;等对方过期后重试即可。
- **崩溃释放靠过期**:不依赖清理任务,也不依赖对方正常退出。
