# 初始化流程

目标:确定这个桶是"已有钱包"还是"新钱包";已有就解锁,没有就建档。

## 1. 选择类型

local 或 s3。

## 2. 填写参数

- **local**:输入 namespace(= `remoteStorageId`)。校验格式;检查本机 device-bootstrap 没有同 id 的连接;再探测本机存储里 `keymaster/keys.json` 是否存在。
- **s3**:输入参数并规范化;检查本机没有相同物理位置的连接;点击"测试连接",读取桶内 `keymaster/keys.json`。

## 3. 判定

| 情况 | 下一步 |
| --- | --- |
| 文件存在且能解析 | 解锁 |
| 文件不存在 | 创建 |
| 读取失败(网络/权限/损坏) | 只允许重试,不能当成"不存在" |

探测读取 `keys.json` 属于《桶锁》的例外,**不需要抢锁**。

## 4. 解锁

1. 输入桶密码,校验 `keys.json` 的 `integrity`(读取 `keys.json` 仍是《桶锁》例外,不抢锁)。
2. 校验成功 → **抢桶锁**:
   - 抢到 → 写 device-bootstrap(记录连接并选中)→ 进入钱包,持锁期间每 45 秒续约。
   - 抢不到 → 停在"桶正被另一个浏览器使用",不进入钱包。
3. 校验失败 → 提示重试;**绝不进入创建,绝不覆盖文件**。

## 5. 创建

1. 输入第一个 Key 的名称和桶密码(这个密码就是以后每次解锁的密码)。
2. **先抢桶锁**(创建是写操作):
   - 抢不到 → 提示"桶正被另一个浏览器使用",不写任何文件。
   - 抢到 → 先写桶内 `keymaster/keys.json`,成功后再写 device-bootstrap(记录连接并选中)→ 进入钱包。
3. 顺序不能反:先写本机会留下"记得桶但没有钱包"的半成品。

## 通用规则

- **锁**:探测/解锁读取 `keys.json`、备份、导出桶不抢锁;其余使用(读和写)都必须持锁,续约失败立即停止全部 I/O。
- 写盘顺序:先桶内文件,后本机 device-bootstrap。
- 密码 = 桶密码 = 解锁密码。
- device-bootstrap 只记录连接;私钥只存在 `keymaster/keys.json`(KeymasterHold v1 文档)。
