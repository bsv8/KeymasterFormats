# 初始化流程

目标:确定这个桶是"已有钱包"还是"新钱包";已有就解锁,没有就建档。

## 1. 选择类型

local 或 s3。

## 2. 填写参数

- **local**:输入 namespace(= `remoteStorageId`)。校验格式;检查本机 device-bootstrap 没有同 id 的连接;再探测本机存储里 `keys/` 目录是否已有可解析的 KeyHold 文件。
- **s3**:输入参数并规范化;检查本机没有相同物理位置的连接;点击"测试连接",读取桶内 `keys/` 目录(KeyHold 文件)。

## 3. 判定

| 情况 | 下一步 |
| --- | --- |
| 至少一份 KeyHold 文件可解析 | 解锁 |
| 目录不存在或没有可解析文件 | 创建 |
| 读取失败(网络/权限/损坏) | 只允许重试,不能当成"不存在" |

探测读取 `keys/` 下的 KeyHold 文件属于《Key 应用锁》的例外,**不需要抢锁**。

## 4. 解锁

1. 解开桶参数(device-bootstrap 的密封 `config`):
   - **s3**:输入**引导密码**;
   - **local**:没有桶参数密文,不需要引导密码。
   读取 `keys/` 下的 KeyHold 文件仍是《Key 应用锁》例外,不抢锁。
2. 解开成功 → 写 device-bootstrap(记录连接并选中)→ 进入钱包。
3. 解开失败 → 提示重试;**绝不进入创建,绝不覆盖文件**。
4. 进入钱包后:选择要用的 Key,输入**该 Key 自己的密码**(KeyHold 文档);每把 Key 密码可以不同。验证通过后**获取该 Key 的应用锁**:
   - 抢到 → 正常使用,持锁期间每 45 秒续约;切换 Key 时先抢新 Key 的锁,成功后再放旧 Key 的锁。
   - 抢不到 → 提示“该 Key 正被另一个浏览器使用”,不使用这把 Key,可以换一把 Key。

## 5. 创建

1. 设置密码:
   - **s3**:设置**引导密码**(以后用来解桶参数),再输入第一个 Key 的名称和**它自己的密码**(KeyHold 文档);两个密码可以相同,但互不关联;
   - **local**:没有桶参数密文,**不设引导密码**,只输入第一个 Key 的名称和它自己的密码。
2. **先抢新 Key 的锁**(创建是写操作,新 Key 的锁天然空闲),再写桶内 `keys/<公钥>.keyhold`(第一份 KeyHold 文档);成功后再写 device-bootstrap(记录连接并选中)→ 进入钱包,持锁期间每 45 秒续约。
3. 顺序不能反:先写本机会留下"记得桶但没有钱包"的半成品。

## 通用规则

- **两个密码域**:引导密码只保护桶参数(仅 s3 有);每把 Key 有自己的密码,导入的 KeyHold 文档保留原密码。
- **锁**:锁按 Key 分开;探测/解锁读取 `keys/` 下的 KeyHold 文件、备份、导出桶不抢锁;使用某把 Key(读和写)必须持有该 Key 的锁,续约失败立即停止该 Key 的全部 I/O。不同 Key 的锁互不影响。
- 写盘顺序:先桶内文件,后本机 device-bootstrap。
- device-bootstrap 只记录连接;私钥只存在 `keys/<公钥>.keyhold`(KeyHold 文档)。
- **导入 / 导出只针对单把 Key**:导出 = 取出 KeyHold 文档,不需密码;不备份桶参数。
